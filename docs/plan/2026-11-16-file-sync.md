# File and folder sync: spec and plan

Date: 2026-11-16. Status: approved by Max 2026-11-16 (v2, after an Opus review). Branch `feat/file-sync`.
Target version 0.2.0. Based on a code map of 0.1.3 (protocol, net, Windows, macOS/Linux/agent).

## 1. What Max asked for (2026-11-16)

- Copying a file, several files, a folder or a zip on one device makes it pasteable on the others.
- **Automatic only for small copies.** A file copy (Ctrl+C / Cmd+C in Explorer, Finder, Prism, a file
  manager) syncs by itself when its total size is at or under a limit: setting, default **100 MB**.
- **Bigger copies go through a picker.** The app window has **Copy files…** and **Copy folder…**, which
  open the system file picker (like VS Code). What is picked becomes the latest copy on every device,
  at any size. `uc copy <path>...` does the same in the terminal.
- Settings: **Sync files** (on/off) and **Largest file copy to sync automatically (MB)**.
- Received files live in a "Universal Clipboard" folder in the user's cache/temp space; the files of
  the last 3 file copies are kept.
- A newer copy (of anything) cancels a file transfer that still runs.

## 2. Behaviour

### 2.1 Copy on the sending device
1. The clipboard holds file references (Windows `CF_HDROP`, macOS `public.file-url`, Linux
   `x-special/gnome-copied-files` / `text/uri-list` with `file:` URIs). When it does, the copy is a
   **file copy**: text and image parts next to it (Finder's name text and icon, a browser's bitmap)
   are ignored.
2. Checked first, as today: our marker (layer 1), our own write (layer 2), private, paused. Then: if
   **Sync files** is off, skipped with the note "Files are not synced (setting is off)."
3. The agent **walks** the items off the main loop (folders recursively, sizes summed). The window and
   `uc status` show "Preparing files…" with a count. Any newer local change or applied remote copy
   cancels the walk (a generation number; a stale result is dropped).
   - Total over the limit (automatic copies only): not sent. Note: "Files over 100 MB are not sent
     automatically. Use Copy files… in the app." The limit is checked **on the copying device only**;
     the help text says "on this device".
   - Otherwise the agent hashes each file (BLAKE3; mmap + multithreaded for files of 16 MiB and up)
     and builds the **manifest**. Only then does the engine take a clock stamp, if the generation is
     still current, and the copy becomes the latest copy ("newest wins" with text and images).
4. **Picker / `uc copy`**: same walk and hash, no byte limit (entry, depth and manifest limits still
   apply, each with its own note). The engine sets the copy as current first; then the agent puts the
   picked items on the local clipboard **with our marker** and records the write as our own, so the
   watcher does not treat it as a new automatic copy (no "over the limit" note for it).
   `uc copy` makes paths absolute in the CLI before calling the agent and fails clearly on a missing path.

### 2.2 Receiving device
1. An offer arrives (small header: id, origin, stamp, total, count, manifest hash, picked yes/no). The
   engine observes its stamp (so a later local copy is always newer) and keeps it as **pending**, one
   at a time. The current copy does not change yet.
   - An offer older than 1 hour, or one that arrives while paused, is only remembered; nothing is
     fetched (same rule as text and images).
2. If the pending offer is the newest copy: free space check on the volume of the files folder (needs
   total + 10 %), then `FilesWant`. The sender opens a data stream (section 3).
3. Data goes to `<files dir>/<id>-<attempt>.part/` (one per attempt, review fix 2026-11-16). The manifest comes first on the stream and is checked
   against the hash and the path rules (2.5) before any file byte is written. Each file is checked
   against its hash. When all are done, handles are closed and the folder is renamed to
   `<files dir>/<id>/` (same volume; on Windows the rename retries for up to 2 s while Defender or the
   indexer hold the new files).
4. The agent writes the clipboard (file references to the top-level items, with our marker), then
   tells the engine `files_applied(id, seq)`: that sets the current copy and the own-write sequence,
   so the files are never sent back.
5. **Single small image:** if the copy is one image file (png, jpg, gif) within the image limit, the
   receiver also puts the image itself on the clipboard next to the file reference, so pasting into a
   chat or document works too.
6. Last activity: "Files received from Max's Mac: 3 files, 12 MB". During the transfer: progress
   (done / total) in the window and `uc status`.
7. Cancelled (partial folder deleted, note says why) by: a newer copy of anything, **Sync files** off,
   pause, hash mismatch, a stream that sends more than declared, a write error (disk full, quota:
   "Not enough disk space for files from <device>"). After a reconnect (Wi-Fi blip, wake, network
   change) the receiver asks again from the start if the offer is still the newest, at most 3 times,
   then gives the note. No byte-level resume in v1.
8. **Long paths on Windows**: the receive root stays short (8-character id). If a path is over 259
   characters the copy is still placed and the note says "Some paths are too long for Windows Explorer".

### 2.3 Sender-side failures
- A file that cannot be opened (locked, sharing violation, permission or macOS privacy denied) aborts
  the send; the note gives counts only.
- A file that changed since the hash (size or mtime) aborts the send: "A file changed while it was
  sent. Copy it again."

### 2.4 Not synced in v1 (skipped with a clear note)
- Virtual files without a path: Outlook attachments, items inside a zip opened in Explorer
  (`FileGroupDescriptorW` only), macOS promised files.
- Cloud placeholders not on disk (OneDrive online-only, iCloud evicted): **the whole copy** is skipped,
  because reading them would download them.
- Symlinks / junctions inside folders are left out; the folder is still sent and the note says
  "N links were left out; apps and bundles may not work".
- Cut (move) is sent as a copy; the source is never deleted.
- Phones (iOS, Android): later.

### 2.5 Storage and names
| OS | Files folder |
|---|---|
| Windows | `%LOCALAPPDATA%\Temp\Universal Clipboard[-profile]\` |
| macOS | `~/Library/Caches/Universal Clipboard[-profile]/` (not `$TMPDIR`, which macOS purges) |
| Linux | `$XDG_CACHE_HOME/Universal Clipboard[-profile]/` (not `/tmp`, often RAM) |

- Keep the last 3 **file** copies. Never delete a folder that is current, pending, or the source of a
  running send (a received folder copied again from here is a send source). Folders older than 7 days
  and `.part` leftovers are deleted at agent start. Test profiles use `<state dir>/files`.
- Manifest entries: relative `/`-separated path, size, BLAKE3, kind (file or folder, so empty folders
  arrive), exec bit (set as mode `0o755`/`0o644` on macOS/Linux receivers). Names are NFC (the sender
  normalizes before hashing, so the same folder hashes the same on every OS).
- Path rules, checked before anything touches disk: no `..`, no absolute or drive paths, no empty
  parts, no NUL, at most 255 bytes per part and 4,096 per path, at most 100,000 entries, depth 64.
  Windows receivers: `< > : " | ? *` and control characters become `_`, trailing dot/space trimmed,
  reserved names (`CON`, `NUL`, `COM1`…) get `_`. Duplicate names (also case-insensitive, also at the
  top level) get ` (2)`.

## 3. Protocol (compatible with 0.1.x peers)

Today one QUIC stream per peer carries `[version][type][postcard body]` frames. Old peers ignore
unknown message types and trailing bytes after a known body, but an unknown `Format` inside
`Latest`/`Clip` makes them close the link. So:

- `Format` and `ClipHeader` do **not** change; files never appear in `Latest` or `Clip`. While the
  current copy is files, `Latest { header: None }` is sent.
- **Features**: `HelloExt { features: u32 }` (bit 0 = files) is appended after **both** Hellos (the
  agent's gate Hello and the engine's Hello), built by one shared function. A new peer parses it from
  the remaining bytes, else features = 0. Every future Hello field goes into `HelloExt`.
- New message types (tags 9 to 11), small:
  - `FilesOffer { id, origin, stamp, total: u64, count: u32, manifest_hash, picked: bool }`
  - `FilesWant { id }`, `FilesCancel { id, reason: u8 }`
- **Who offers**: only the origin device offers and serves a file copy; receivers never re-offer.
  Offers are never sent from `connect`; they go out from `on_hello` once the peer's engine Hello shows
  bit 0 (gate rules: nothing but Hello and Membership before the gate opens). A peer without the bit
  gets the note "Max's Mac needs an update to receive files."
- **Data stream**: one unidirectional QUIC stream per transfer, priority −1 (clipboard frames go
  first). Content: header `{ copy id }`, then the manifest (length-prefixed, at most 16 MiB, checked
  against `manifest_hash`), then each file's bytes in manifest order. The receiver accepts a stream
  only if the id matches its outstanding `FilesWant` to that peer and it arrived on that peer's
  current member link; any other stream is stopped at once. More bytes than declared aborts.
- **Cancel**: the sender resets its stream (`reset(code)`), the receiver stops it (`stop(code)`):
  code 1 = superseded, 2 = aborted.
- **Echo layer 4**: content hash for files = BLAKE3 over `uclip/files/1` + the manifest.

## 4. Engine (uc-core, stays pure, no I/O)

- `Current` = `Clip(Held)` or `Files(HeldFiles)`; both use the same clock stamp.
- Local file copy: `on_local_change` returns `Event::WalkFiles { paths, gen }` (after layers 1-2,
  private, paused and the setting). Any later change bumps `gen`. `on_local_files(gen, summary,
  picked, now)` drops a stale gen, ticks the stamp, sets Current, sends offers.
- Remote: `FilesOffer` → observe stamp → pending (or only remembered: too old / paused) →
  `Event::FetchFiles { peer, id }`. `files_applied(id, seq)` → Current, `last_write_seq`, `applied`.
- Any newer copy (local or remote, any kind) emits `Event::CancelTransfer { id }` for the pending fetch
  and the sender's running sends. Disconnect: the pending fetch waits for the same peer to come back
  (retry up to 3 times, section 2.2.7).
- Sends: `FilesWant` for the current files copy → `Event::ServeFiles { peer, id }`. At most 2 sends
  run at once; more wait in a FIFO queue. A new `FilesWant` for the same id from the same peer resets
  its old stream first. A newer Current resets all running and queued sends.
- Skip reasons: `FilesOff`, `FilesOverLimit`, `FilesVirtual`, `FilesCloudOnly`, `FilesTooMany`,
  `PeerNoFiles`.

## 5. Agent, CLI and window

- **Walk, hash and transfers** run in tokio tasks / `spawn_blocking`, never on the main loop.
- **Settings**: `sync-files` (on/off, default **on**), `file-limit-mb` (1 to 10,240, default **100**,
  label "Largest file copy to sync automatically (MB), on this device").
- **Copy action**: IPC `files.copy { paths, picked: true }`; CLI `uc copy <path>...` (plan 3.2 parity).
  It is a *copy* (makes the items the latest copy, like Ctrl+C), so CLAUDE.md's "No send or get
  actions" rule stays true; the rule gets a one-line note.
- **Stop** (decided 2026-11-16): a **Stop** link on the progress line and `uc transfer stop`. It
  cancels the running transfer (sender or receiver side); a new copy also cancels.
- **Window**: Home gets **Copy files…** and **Copy folder…** (`tauri-plugin-dialog`; Windows cannot
  pick files and folders in one dialog), and a progress line ("Preparing files…", "Sending to …",
  "Receiving from …") with Stop. Settings gets the two rows. Max chose **no mockups** (2026-11-16):
  built directly in the locked design's existing components and tokens, new screenshot baselines.
- **Activity and logs**: counts and sizes only, never file names. New IPC event `transfer`
  ({id, phase: preparing|sending|receiving, device, done, total, files}) at most 4 per second.
  `uc status --json` gets `transfer` (current) and `last_transfer_error`.

## 6. Backends (uc-clip)

- `Snapshot` gets `files: Vec<PathBuf>` and `files_virtual: bool`; `Clipboard` gets
  `write_files(&mut self, paths, image: Option<&[u8]>) -> Result<u64, _>` (default unsupported).
  `FakeClipboard` supports both.
- **Windows**: read `CF_HDROP` (DROPFILES, wide paths via `OsString::from_wide`; ANSI skipped);
  `FileGroupDescriptorW` without `CF_HDROP` = virtual; detect `FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS`
  (cloud placeholder). Write in one open: marker, `CanUploadToCloudClipboard = 0`, `CF_HDROP`
  (top-level, absolute, no `\\?\`), `Preferred DropEffect = 1`, and the PNG/DIB for 2.2.5.
  Pure `parse_hdrop` / `build_hdrop` with proptests.
- **macOS**: read file URLs per item (resolve file-reference URLs), fallback `NSFilenamesPboardType`;
  promised files = virtual; evicted iCloud files = cloud-only. Write `NSURL`s via `writeObjects`, then
  the marker; keep `CurrentHostOnly`. Reading Desktop/Documents/Downloads may show a one-time macOS
  privacy prompt: setup row + docs.
- **Linux**: read `x-special/gnome-copied-files`, else `text/uri-list` (`file:` only, percent-decoded);
  write both plus `application/x-kde-cutselection = 0` and the marker. GNOME-on-Wayland paste into
  Nautilus is unverified (spike S4): tested and noted.
- **uc-net**: `max_concurrent_uni_streams` 8 on member data links only (pairing and probation links
  keep 0 or stop every stream), `stream_receive_window` set explicitly, `Link::open_stream`, an
  `accept_uni` loop per link, `NetEvent::Stream { peer, link, stream }` only for the current member
  link with the gate open.

## 7. Tests

- **Core (fake net)**: small copy syncs; over limit skipped; picker over limit syncs; text copied
  during a walk wins (stamp race); offer sent only after the peer's engine Hello; old peer (no bit)
  gets nothing and stays connected; pending offer cancelled by newer text and vice versa; received
  files not re-offered (marker, own seq); same folder twice not re-sent (layer 4); picker write-back
  gives no over-limit note; FIFO with 3 receivers; reconnect retry; hostile manifests rejected.
- **Codec**: `HelloExt` round trip; old Hello without it; new types; byte-exact compatibility with
  0.1.3 frames; never panics (proptest).
- **uc-net loopback**: 1 GB transfer (throughput logged); cancel from each side; wrong-id and
  unsolicited streams stopped; probation link streams refused; link replaced mid-transfer → retry.
- **Windows (winhost)**: CF_HDROP with spaces, non-BMP and many paths; garbage DROPFILES; write then
  formats present and marker seen; virtual-only skipped; 300-character path; locked source file.
- **macOS** (on the Mac, named pasteboard, headless): file URL read/write, marker after `writeObjects`.
- **Linux**: URI parse/build; Docker live X11 + Wayland; disk full via a small loop/quota volume.
- **E2E (`uc-cli/tests/agents.rs`)**: folder with nested files, empty folder, exec bit and a zip;
  over-limit note; `uc copy` of a 300 MB file; newer copy cancels; keep-3 cleanup; single-image
  companion; old-version peer.
- **Network lab (WSL)**: 200 MB over lossy Wi-Fi; sleep/wake mid-transfer.
