# iPhone and iPad app: spec and implementation plan (2026-11-28)

Scope agreed with Max on 2026-11-28: iPhone and iPad only. Android (M13) comes later.
The Simulator part of spike S5 runs now. The real-iPhone part runs when Max plugs the phone in.
The iPad mockups are approved as the layout to build.
This page narrows plan sections 2.6, 3.1, 6.7 and milestones S5, M12 and M14
(`2026-11-13-spec-and-plan.md`). Where this page and the plan disagree, this page wins.

## 1. What the user gets

- One universal App Store app, "Universal Clipboard", for iPhone and iPad. iOS and iPadOS 18 or newer.
- First run (F1 One shape): Welcome, the Local Network prompt, scan the QR code from a computer
  (or type the 6 digits), Connected.
- How it works (W3 One story): open the app to sync. Use the Share sheet from other apps.
  The optional paste setting "Allow".
- Home (H3 Pinned): this device is shown pinned and apart from the others. The list of other
  devices, with their state. The newest copy is shown as facts only (kind, size, from which
  device, when), never the content. The ticker (A3) moves when a copy moves.
- On open, in this order: connect to the members it can reach. Fetch the newest clip and write it
  to the pasteboard (`.localOnly`, so it does not go to Handoff). Read the pasteboard once, and
  share it if it is new.
- Share Extension (X1 Quick): "Universal Clipboard" in the Share sheet. It makes the shared text
  or image the latest copy, then closes.
- Pause (P1 Bar button) and errors (E3 Sheet): wrong or old code, "No computer is on right now on
  this network", Local Network off, VPN blocks the LAN.
- Settings (T3 On Home): device name, device detail, remove a device, "Remove this iPhone and
  forget everything", About.
- iPad: the same screens in a split view. Home is on the left and Settings or detail is on the
  right, in landscape and portrait (`ipad-*.html`).
- The words "send" and "get" never appear. A copy is a copy (project rule).

The app does not have (as plan 2.6 and 9 say): background sync, App Intents, Shortcuts,
Control Center controls, a keyboard extension, file and folder copies, copy history.
File copies stay desktop-only in this round. A phone ignores `Latest` headers for files.

## 2. Architecture

```
SwiftUI app ─┐                      ┌─ uc-core (Engine, role PullOnly)
Share Ext. ──┼─ UcMobile.xcframework ─ uc-mobile ─┼─ uc-net (quinn, iOS binder, no mdns-sd)
             │   (UniFFI Swift)                   ├─ uc-pair (joiner, graph, gate)
Bonjour ─────┘  NWBrowser → Rust callback        └─ uc-member (new, shared with uc-agent)
Keychain group + App Group container (shared by app and extension)
```

- **Transport is plain QUIC (`quinn`), not iroh** (`docs/net.md`, M2). So S5's "iroh through
  UniFFI" question becomes "quinn and ring through UniFFI".
- **New crate `uc-member`**: the link-gating and membership logic that now sits in
  `uc-agent/src/agent.rs` moves here: `Hello` with the group, membership sync, the gate,
  probation, `WantSecret` and `Secret`, applying a `Removed`, and the self wipe. The agent and the
  phone then run the same code. This is a move with no change in behaviour. The agent tests must
  stay green with no edits.
- **uc-mobile** (UniFFI, proc macros, no UDL) has a blocking API with its own small tokio
  runtime:
  - `open(dir, keychain_group)`, `pair(code_or_qr)`, `sync_on_open(clipboard_snapshot) -> SyncResult`
  - `share(parts)`, `status()`, `members()`, `rename(name)`, `remove(device)`, `leave()`
  - `pause()` and `resume()`
  - a callback trait `Bonjour`: Swift sends the instances it finds (name, addresses), and Rust
    checks the HMAC tags.
  - a callback trait `Pasteboard` is not needed: Swift reads and writes the pasteboard, Rust only
    gets and returns bytes.
- **Discovery**: remembered addresses (`LanBook`) first, then Bonjour through `NWBrowser`
  (`_uclip._udp`, `_uclip-pair._udp` in `NSBonjourServices`). `mdns-sd` is not built for iOS.
  No multicast entitlement is needed.
- **Sockets**: an iOS `SocketBinder`. It binds Wi-Fi and wired LAN addresses only, with
  `IP_BOUND_IF` (the same as macOS). `NWPathMonitor` in Swift reports path changes and calls `wake()`.
- **Keys**: a new `uc-keys` backend for iOS. It uses the Keychain with an access group shared by
  the app and the extension, and `kSecAttrAccessibleAfterFirstUnlock`. State (`state.json`,
  `LanBook`) is in the App Group container.
- **Role**: `Role::PullOnly` and `device_type` 4 (iPhone) or 5 (iPad). The full members already
  pass a pull-only client's copy on to the others (`docs/core.md`). Desktops need no protocol change.
- **The extension** opens the same identity. It connects, sends one copy, and closes within
  about 5 s. Target: under 2 s and under 60 MB (the extension limit is about 120 MB).
- **Xcode project**: `apps/ios/project.yml` (XcodeGen, installed), so the `.xcodeproj` is
  generated and not committed. The targets are App, ShareExtension, AppTests and AppUITests.
  Swift 6, SwiftUI. Fonts and colors come from `docs/design/ios`.
- **Build**: `apps/ios/build-rust.sh` builds the targets `aarch64-apple-ios` and
  `aarch64-apple-ios-sim`, runs `uniffi-bindgen` and makes `UcMobile.xcframework` (git-ignored).
  It uses the shared `CARGO_TARGET_DIR`.
- **Version**: the app takes `CFBundleShortVersionString` from `workspace.package.version`.

## 3. Testing (headless, never Max's screen or clipboard)

- **Rust host tests** (`uc-mobile`, `uc-member`): a pull-only client pairs with a real agent on
  loopback (`UCLIP_PROFILE` test profiles), runs `sync_on_open` both ways, shares, is removed,
  and gets "no full member".
- **Simulator**: `xcodebuild test` on a headless simulator (`simctl boot`, Simulator.app never
  opened). XCTest covers the app logic, and XCUITest covers every screen. Screenshots of every
  screen and state, light and dark, iPhone and iPad. They are checked once against the
  mockups by an independent review, then become baselines (1% rule, as for the desktop).
- **Pasteboard safety**: the Simulator syncs its pasteboard with the Mac only through
  Simulator.app, and that is never opened. Tests also use a named `UIPasteboard`, not the
  general pasteboard. The only exception is one marked live test, which runs with sync checked
  off first.
- **Live LAN test**: the Simulator shares the Mac's network. A `dev`-profile agent on this Mac
  (fake clipboard) pairs with the app in the Simulator and syncs text and an image both ways.
  The same test against the PC runs when SSH to the PC works.
- **Not accepted from the Simulator** (it does not enforce them): paste prompts, the Local
  Network prompt, and a VPN on the phone. These are on the real-device checklist.
- **Real devices (later, your yes)**: an S5 part 2 build is installed on your iPhone over USB
  with Xcode. Then the TestFlight checklist on the iPhone and the iPad (about 15 minutes each).

## 5. Risks

- **The ring and quinn build for iOS** might need an extra step (for example a newer `cc`, or
  `IPHONEOS_DEPLOYMENT_TARGET`). PR 1 finds out.
- **The extension's memory**: tokio plus rustls must stay small. The fallback is a single-thread
  runtime and no image decode in the extension.
- **Moving code out of `agent.rs`** (2,739 lines) is the largest refactor so far. It goes in its
  own PR, with the tests unchanged.
- **The Simulator's pasteboard and Local Network** do not match a real iPhone. Row 7 covers that.
- **Signing**: the Simulator builds are unsigned. A device and TestFlight build need the Team ID,
  an App ID with an App Group and Keychain sharing, which are set up in row 7.
