# Tray and menu bar icon (0.3.0): spec and plan

Status: approved by Max on 2026-11-17, built on `feat/tray`. Notes from the build are marked "Build:".
Design (approved by Max on 2026-11-17): `docs/design/tray/panel.html`, with the dark panel and minimal text. The icon is A (three layers), from `docs/design/tray/index.html`.

## 1. Decision change

The base plan says "No system tray icon" in section 1, 2.2, 2.7 and the risk table. PRODUCT.md and docs/desktop.md say the same.
On 2026-11-17 Max asked for a tray icon on Windows, a menu bar icon on macOS and an icon on Linux.
The reason: you can see the sync state at a glance and reach Copy files, Pause and Quit in one click.
The decision changes in this order:
- An icon is shown by default. The setting "Show icon in the taskbar" (Windows and Linux) or "Show icon in the menu bar" (macOS) turns it off. The setting key is `tray-icon`, and the default is on.
- With the icon off, the app behaves as before: there is no icon and no Dock icon, and the window opens when you start the app.
- The notification rules in 2.7 stay. The icon state is an extra signal, not a replacement.

Docs to update in the same PR: the plan lines that say "no tray icon", PRODUCT.md, docs/desktop.md and the "Our edge is ... no tray" risk row.

## 2. What the user sees

### 2.1 The icon

| State | Windows and Linux | macOS (template image, one colour) |
|---|---|---|
| Synced or idle | Icon A | Icon A |
| Sending or receiving | Icon A with a down arrow badge | the same |
| Paused | Icon A with a pause badge (two bars) | the same |
| Needs attention, or the agent does not run | Icon A with an amber dot | Icon A with a dot |

Build: the badges are the ones from the icon mockup (`docs/design/tray/index.html`), static, in
place of a pulse and an opacity change. On Windows the icon is white on a dark taskbar and black
on a light one.

The tooltip is the state word: "Universal Clipboard: Synced", "... Paused", "... Not connected", or "... Receiving 40 %".

### 2.2 Click

- **Windows and macOS:** a left click opens the dark panel next to the icon. A second click, Esc, or a click anywhere else closes it. On Windows it opens above the taskbar, aligned to the icon (or below the icon when the taskbar is on top). On macOS it opens under the menu bar icon.
- **Windows right click:** this opens the same panel. There is no second menu.
- **Linux:** AppIndicator does not report clicks, so Linux gets a native menu with the same actions. The first line shows the state ("Synced", "Paused", "Receiving 40 %"), and you cannot click it.

### 2.3 The panel (as in panel.html)

- **Header:** the state word, the lamp, a one-line fact only for Synced ("Text from Max's Mac, 2 min ago"), and the device chips.
- **Transfer row:** only while files move. It has an up or down arrow, a bar, the percent, and an x that stops the transfer. There is no other text.
- **Not connected:** shows the one note "Can't reach your other device? Your VPN blocks the local network." with "Show me how" (it opens the window on VPN help). Other attention states use their own sentence from plan 2.7, and their Fix opens the window on that screen.
- **Two buttons:** Copy files... and Copy folder... They open the system picker. The picked items become the latest copy (`files.copy`).
- **Sync switch:** Pause or resume (`pause.set`).
- **Footer:** "Open Universal Clipboard" (the window), Settings (the window on Settings), and Quit.
- **Quit** stops the agent and closes the icon. Sync stays off until the next login or until you open the app again. There is no confirm dialog. The tooltip says "Quit (stops syncing)".

Size: 320 px wide, as in the mockup. The height fits the content. The panel is always dark.

## 3. How it works

### 3.1 One process for the icon and the window

The window binary (`Universal Clipboard.exe`, `universal-clipboard`, the .app) gets a tray mode.
- **`--tray`:** start with no window and show the icon. The agent starts the binary this way at its own start, but only when `tray-icon` is on and the profile is not a test profile. Test profiles append "tray" to `<state>/update/window-opens.log` and start nothing, like `open_window` does today.
- **Single instance (already used):** a second start goes to the running process. A start with no arguments opens the window. A start with `--tray` adds the icon if it is missing. A start with `--route update` works as today.
- **Lifetime:** while the icon is shown, closing the window or the panel does not end the process (`RunEvent::ExitRequested` is prevented unless Quit or "icon off" asked for the exit). With the icon off, closing the window ends the process, as today.
- **Window config:** `main` is no longer created at start (`"create": false`). The process creates it on demand: on a normal start, from the tray, or from `--route update`.
- **macOS:** `LSUIElement` stays (no Dock icon). A `--tray` start does not activate the app or show a window. Linux and Windows show no taskbar button for the panel (`skip_taskbar`).

### 3.2 The panel window

- The panel is a second webview window with the label `panel`. It is borderless, does not resize, stays on top, has no taskbar button, and has a transparent edge for the rounded corners and the shadow. It loads the same frontend with `#panel`, and `App.svelte` renders `Panel.svelte` for that hash.
- It is created on click and destroyed when hidden, so it uses no memory while closed. Target: the panel shows within 150 ms of the click on this PC (WebView2) and on the Mac. If it is slower, keep it created and hidden after the first open. Measure both and record the numbers in docs/desktop.md.
- Placement is a pure function `panel_position(icon_rect, monitor_work_area, panel_size, os) -> (x, y)`. It keeps the panel inside the work area on every monitor and at every DPI. Unit tests cover the taskbar at the bottom, top, left and right, the macOS menu bar, and a second monitor.
- It hides on focus loss (`WindowEvent::Focused(false)`), except while a file picker started from it is open.
- The capability `default.json` adds `panel` to its windows, so the panel can receive `uc-event`.

### 3.3 Actions run in Rust

The panel and the Linux menu call one set of Tauri commands. A panel can be gone (focus loss, picker) before an action ends, so the page never holds an action:
- `tray_copy(folder: bool)`: hide the panel, open the picker with no parent window, then send `files.copy` with the picked paths. Cancel does nothing.
- `tray_pause(on: bool)`: `pause.set`.
- `tray_stop()`: `transfer.stop`.
- `tray_open(route: Option<String>)`: create or show `main`. The route can be `settings`, `vpn-help`, or an attention screen.
- `tray_quit()`: send `quit` with the non-starting `Client::connect` (not `uc_cli::connect`, which starts a missing agent), then exit the process without any further call.

`pick_paths` (for the window's Home screen) keeps its parent window, but only when `main` exists.

### 3.4 Icon state lives in Rust

A task in the tray process keeps one subscription to the agent (`Client::connect`, which never starts the agent). It listens for `status` and transfer events and sets the icon, the tooltip and the Linux menu. The rules are in a pure function `tray_state(status_json) -> TrayState`, with unit tests.
- **Agent gone (crash or update):** the icon shows "Not running" (the attention dot), and the task tries again every 2 s. Build: a `--tray` process that finds no agent for a minute and has nothing on screen exits. It does not start the agent. Login (launchd, Run key, supervise) or the window does that.
- **Agent quit by `uc quit` or another Quit:** the agent sends the event `quitting` before it exits. The tray process exits too.
- **`tray-icon` turned off** (window or `uc`): the agent sends `settings` with the new value. The tray removes the icon, and exits if no window is open. Turned on: the agent starts `--tray`.

### 3.5 Quit and the CLI

- `quit` moves from `SERVICE_CALLS` to `CALLS`, so the window can use it (the `list_matches_the_agent` test stays true). The installers still use it.
- A new command, `uc quit`: "Stop Universal Clipboard on this device until the next login or until you open it again." It exits 0.
- The agent exits with code 0 after `quit`. macOS `KeepAlive {SuccessfulExit=false}` and the Linux supervisor do not restart it. A test checks the exit code.
- `uc settings set tray-icon on|off` and the Settings screen row (a switch, in General under "Start at login").

### 3.6 Update and install

- **Windows NSIS:** `close-app.ps1 -Phase window` already ends `Universal Clipboard.exe` from the install folder (WM_CLOSE, then a forced stop after 5 s). After the install, the new agent starts and starts `--tray`. `test-install.ps1` checks that the tray ends with the agent before it replaces the file. Build: the tray has no top-level window for WM_CLOSE, so the installer may need the 5 s forced stop; nothing is lost.
- **Self-update (Windows and macOS):** the helper stops the agent. The tray sees the agent go and shows "Not connected" without exiting, so the old tray would hold the files. So the helper also ends the tray process from the install folder before it swaps the files (the same path filter), and the new agent starts a new `--tray`. A test covers this in `tests/update.rs`, with the test profile `window-opens.log`.
- **macOS .app:** the same `--tray` start goes through `open -a <app> --args --tray`.
- **Linux .deb:** add `libayatana-appindicator3-1` to `Depends` when the window is built. `test-deb.sh` checks that apt installed it (it is loaded at run time, so `ldd` does not show it). Build: no `--check` flag; a GTK app cannot start without a display.

### 3.7 Icons

- A source SVG for each state, in `packaging/assets/tray/`.
- PNGs are rendered by a script (`tools/tray-icons.mjs`, headless Edge or resvg) and committed: 16, 20, 24 and 32 px for Windows and Linux, and 18 and 36 px template PNGs for macOS (`icon_as_template(true)`).
- The icons are included in the binary (`include_bytes!`).

## 6. Out of scope

- Clip history in the panel.
- A list of recent copies.
- Notifications from the icon (the rules in plan 2.7 stay).
- Linux panel (only the native menu, because AppIndicator has no click event).
